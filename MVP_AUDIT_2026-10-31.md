# Group Buying MVP — code audit and remediation (2026-10-31)

## Repository baseline

- Source branch: `group-buying`
- Review branch: `fix/mvp-foundation-20261031`
- No production deployment, live data edits, or payment processing performed.
- This report describes code changes and static inspection, **not** successful runtime validation.

## Confirmed baseline gaps

1. Laravel application entrypoints and bootstrap files were missing, so `php artisan` was not runnable from the repository.
2. Sanctum token table migration was missing.
3. Product migration attempted a foreign key to categories before creating the categories table.
4. Order code referred to `address_id` that was absent in the orders schema.
5. Controller code used Eloquent relationships absent from models.
6. Documented admin endpoints were not registered.
7. Admin/vendor ownership and campaign confirmation were not authorized.
8. Customer checkout calculated ordinary product prices without linking an order to a completed campaign.
9. Campaign joining ignored campaign dates and stock constraints.
10. Flutter used `localhost` as API address, and initialized Firebase without a complete platform configuration.

## Remediation on isolated review branch

- Added Laravel application entrypoints, bootstrap, configuration, cache/storage locations and routing.
- Added Sanctum tokens and additive schema fixes, including unique participation/order constraints.
- Added model relationships, role-protected admin routes, and vendor ownership validation.
- Restricted product and campaign publishing to active vendor stores.
- Added date, minimum-participant and stock checks, transactional campaign join/confirmation and order writes.
- Order creation now requires a fulfilled campaign, a participating customer, a customer-owned delivery address, and cash-on-delivery payment; it rejects repeat orders and calculates the campaign price on the server.
- Added customer delivery-address API endpoints and Flutter API integration, with a configurable development API URL.
- Made Firebase initialization opt-in until Firebase platform configuration exists.
- Added starter access-control tests and a CI workflow.

## Remaining work — not verified

- Execute `composer install`, `php artisan migrate`, `php artisan route:list`, and `php artisan test` with working PHP extensions and database.
- Flutter project still needs generated Android/iOS scaffolding and real-device testing; run `flutter analyze` and `flutter test`.
- Admin tooling must support store approval and moderation; merchant self-service and operational order status workflows are incomplete.
- Need tested stock reservation/expiry policies, campaign cancellation, refunds/returns procedures for COD, fulfillment deadlines, delivery charges, and notification workflows.
- Need security review (token lifecycle, throttling, privacy, input limits), automated feature tests and concurrent participation/order tests.
- Configure Firebase, TLS, backups, server infrastructure, product catalogue and launch agreements before deployment.
- Launch targets (five vendors, fifteen–twenty products, three–five campaigns, fifty orders) remain **planning assumptions**, not confirmed outcomes.

## Important business decision

For the MVP, participation is not a purchase: a participating customer places the cash-on-delivery order only after campaign confirmation. This is a provisional policy and should be confirmed before release. A different flow (pre-order/commitment first) requires a different stock and cancellation model.
