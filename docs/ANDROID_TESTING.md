# Android debug build — testing only

The Android project runner is currently generated by the CI job because the repository
does not include the platform directory. This does **not** publish the application.

## Build from GitHub

1. In GitHub Actions choose **Android debug APK (test only)**.
2. Use **Run workflow** on branch `fix/mvp-foundation-20261031`.
3. For physical-phone testing, provide `api_base_url` as a working HTTPS staging
   endpoint ending with `/api` (for example, `https://staging.example.com/api`).
   Alternatively configure the repository Actions variable `STAGING_API_BASE_URL`.
4. When the run succeeds, find `gam3ni-android-debug-apk` in its **Artifacts**.
   It is a **debug APK** for internal testing, not a signed release APK.

Without a staging URL, the build points to the Android emulator loopback
`http://10.0.2.2:8000/api`. It will **not connect** on a physical phone outside
the developer's emulator. No real staging backend is configured by this change.

## Before calling the Android app ready

- Build and install on a physical Android device.
- Test a real account flow over HTTPS against an isolated staging database.
- Verify joining and confirmation, address entry, checkout, order tracking.
- Test slow network, retry, cancellations, expired campaigns, and logout.
- Protect the staging server (test users, isolated data, access controls).
- Add platform Android files permanently, a unique application id, icons, and
  signing configuration before any distribution.
- Obtain approval before enabling production connectivity or app release.
